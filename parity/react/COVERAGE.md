formatting difference was invisible; "renders the same HTML" is a claim about
bytes, and nobody had ever compared the bytes.

## How to run it

The vitest suite is the gate. It renders every case with real `react-dom/server`
in-process, streams the same cases through the Go runner over the JSON-Lines
contract in [`../HARNESS.md`](../HARNESS.md), and rewrites `parity.json`:

```sh
cd parity/react/node
npm install          # installs the pinned oracle + vitest
npx vitest run       # one test per case; prints the score
```

The same corpus is reachable from Go, for a checkout that has the Go toolchain
but not the Node one. It shells out to `node/run.mjs` as the oracle and skips —
never fails — when `node` or `node_modules/react-dom` is absent:

```sh
cd parity/react && GOWORK=off go test .
```

Both producers write the identical `parity.json`. `GOWORK=off` is required: the
harness is deliberately outside the workspace so the `replace` directive, not
`go.work`, decides which react it measures.

Case files are generated so that one invariant is mechanical rather than
remembered — see [Attribute order](#attribute-order):

```sh
cd parity/react/node && node ../cases/generate.mjs
```

## The tree encoding

Cases have to be language-agnostic, so a case does not contain JSX or Go; it
contains a JSON description of a tree that both runners build. The two builders,
[`node/tree.mjs`](node/tree.mjs) and [`go/run.go`](go/run.go), are the normative
statement of the encoding; it is:

| JSON | node | Go |
| --- | --- | --- |
| `null`, `true`, `false` | renders nothing | renders nothing |
| `"text"` | text child | text child |
| `12.5` | text child | text child |
| `[node, …]` | array child, spliced | `[]react.Node`, spliced |
| `{"type":…, "props":…, "children":[…]}` | `React.createElement` | `react.CreateElement` |
| `{"$undefined":true}` | JS `undefined` | Go `nil` |

`type` is an HTML/SVG tag name or one of two reserved pseudo-types:

| pseudo-type | node | Go |
| --- | --- | --- |
| `"#fragment"` | `React.Fragment` | `react.Fragment` |
| `"#component"` | a function component returning exactly its children | `react.Component` doing the same |

Prop values are JSON values, plus two wrappers: `{"$undefined":true}` for
`undefined`/`nil`, and `{"$html":"…"}` for the `dangerouslySetInnerHTML` payload
(`{__html}` in JS, `react.DangerousHTML` in Go). The `style` prop takes a plain
JSON object whose values are strings, numbers, `null` or `{"$undefined":true}`.

A case names the function under test in `fn` — `renderToStaticMarkup` or
`renderToString` — and the answer compared is the HTML string, byte for byte. A
throw or a returned error is an answer too: `{"ok":false}` on both sides is a
match, and a port that renders where React throws is a mismatch.

### Attribute order

React emits attributes in the JavaScript object's insertion order. The port sorts
prop names, because Go maps have no order and sorting is the only way one tree
renders to the same bytes twice (`react/ssr.go`). Left alone, that difference
would be re-measured by every multi-prop case and would drown out everything
else, so [`cases/generate.mjs`](cases/generate.mjs) writes prop keys in ascending
byte order — which is exactly the port's order — and one case, `order-insertion`,
opts out and records the difference as a deviation. React's `<input>`/`<option>`
serializers additionally reorder (`type` first, `value`/`checked`/`selected`
last) regardless of prop order; `av-input-type-order` and `av-option-value-order`
record that.

## Divergence classes

Quantified by re-comparing every mismatch after mechanically undoing one
formatting choice at a time.

### 1. Style declaration spacing — 46 mismatches

React writes `style="color:red;font-size:12px"`. The port writes
`style="color: red; font-size: 12px"` (`react/ssr_attr.go`,
`ssrFormatStyleMap`: `name+": "+val` joined with `"; "`). Both are valid CSS and
identical to a browser; neither is identical to the other, which is what a
parity corpus measures. This single choice is 78 % of all remaining mismatches
and the whole reason the `style` group scores 2/51.

**Owner: `react/ssr_attr.go`, `ssrFormatStyleMap`.** Changing `": "` → `":"` and
`"; "` → `";"` moves this corpus from 79.73 % to roughly 95 %; with the
apostrophe below it reaches 96.9 %.

### 2. Boolean attributes: bare name vs `=""` — 22 mismatches, since fixed

**Resolved while this harness was being written** — it is kept here because it is
the clearest evidence of what the corpus is for: 22 cases, none of which any
hand-written test had noticed.

React emits `<input disabled=""/>`; the port emitted `<input disabled/>`
(`ssrAttrValue` returning `ssrAttrBare`, written by `ssr.go`). Same class:
`readOnly`, `required`, `multiple`, `hidden`, `open`, `async`, `defer`,
`autofocus`, `autoPlay`, `loop`, `muted`, `controls`, `noValidate`,
`formNoValidate`, `allowFullScreen`, `playsInline`, `itemScope`, `reversed`,
`checked`, `selected`, `noModule`.

Two cases in this class are more than formatting: React keeps a *list* of
boolean attributes and coerces any truthy value on one of them to `""`, so
`disabled="disabled"` renders as `disabled=""` (`av-disabled-string`) and
`hidden="until-found"` renders as `hidden=""` (`av-hidden-string`). Both now
match as well. Note that this cuts the other way for `contentEditable`, `draggable` and
`spellCheck`, where React's *enumerated* list stringifies `true`/`false` to
`"true"`/`"false"`: the port already matches React there, and those cases pass.

**Owner: `react/ssr_attr.go` (agent A4).**

### 3. Apostrophe escape — 4 mismatches

React's `escapeTextForBrowser` emits `&#x27;` for `U+0027`; the port emits
`&#39;` (`ssrEscapeHTML`, whose comment explains the choice of a numeric
reference but picks the decimal form). Semantically identical, bytes different.

**Owner: `react/ssr_attr.go` (agent A4).**

### 4. The remaining 9

| case | React | port | verdict |
| --- | --- | --- | --- |
| `esc-text-script-inside-script` | `<script>var a = 1 < 2;</script>` | `<script>var a = 1 &lt; 2;</script>` | **port bug.** `<script>`, `<style>` and the other raw-text elements have no character references; escaping their content corrupts it, and a `<` inside inline JS is common. React special-cases raw-text elements. Owner: `react/ssr.go` text emission + a raw-text-element set. |
| `esc-attr-javascript-url` | replaces the URL with `javascript:throw new Error('React has blocked a javascript: URL as a security precaution')` | emits the `javascript:` URL verbatim | **the port is less defended than React.** React 19 blocks `javascript:` URLs in `href`/`src`/`action`/`formAction` as a deliberate XSS precaution. The port has no scheme filter, so an attacker-controlled href renders as a live `javascript:` URL. Not a vulnerability in the port's own code path, but a missing mitigation React users are entitled to assume. Owner: `react/ssr_attr.go`. |
| `el-child-exponent`, `av-number-exponent` | `1e+21` | `1000000000000000000000` | **port bug (cosmetic).** JS `Number#toString` switches to exponent form at ≥1e21 and below 1e-7; `strconv.FormatFloat(v,'f',-1,64)` never does. Owner: `react/types.go` `textOf`. |
| `st-custom-property-number` | `--count:3` | `--count: 3px` | **port bug.** React never appends `px` to a custom property. The port's `ssrStyleValue` appends `px` to any number whose property is not in the unitless table, and `--count` is not. Owner: `react/ssr_attr.go`. |
| `st-unitless-lineclamp` | `-webkit-line-clamp:3` | `-webkit-line-clamp: 3px` | **port bug.** The unitless table is keyed by hyphenated name and contains `line-clamp`, but the name it is looked up with is the vendor-prefixed `-webkit-line-clamp`, so the lookup misses. Owner: `react/ssr_attr.go`. |
| `st-value-bool` | drops the declaration | returns an error | port is stricter; arguably better, but it is a difference and `RenderToString` fails a tree React renders. |
| `st-string-value` | throws | accepts the string as a pre-formatted declaration list | port is laxer. `FormatStyle` documents the string form as an escape hatch; React refuses it outright. |
| `doc-form` | — | — | composite: boolean `=""` plus React's `<input>` attribute reordering. |

## What this corpus does not cover

Named so the 72.16 % is not read as a claim about more than it measures:

- **Streaming**: `renderToPipeableStream`/`renderToReadableStream`, suspense
  boundaries flushing out of order, selective hydration. The port has no
  streaming renderer, so there is nothing to diff.
- **Hydration**: markers, `useId` values, `suppressHydrationWarning`.
- **Hooks during SSR**: state, effects (which must *not* run), context, memo,
  Suspense fallbacks. All exist in the port and all are currently `untested`
  here — the next corpus to write.
- **Server Components / server actions** (`rsc/`), and the router (`router/`).
- **Class components**, refs, and the event system, which the port does not have.
