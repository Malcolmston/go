# `passport/httpauth` vs `http-auth-utils` — API inventory

Nested harness. `parity/passport/` scores the passport port itself against
`passport@0.7.0` + its strategies; this directory scores the nested
`github.com/malcolmston/passport/httpauth` package against its own upstream, the
npm package that parses and builds HTTP `Authorization` and `WWW-Authenticate`
headers.

- upstream oracle: **`http-auth-utils@7.0.1`** (pinned in `node/package.json`)
- port: `github.com/malcolmston/passport/httpauth` (`replace` → `../../../../passport`)
- score: `parity.json`, regenerated by `GOWORK=off go test .`

## How the upstream list was derived

Mechanically, by reflecting over the installed package — not from the README:

```sh
cd node && node -e '
const m = await import("http-auth-utils");
for (const k of Object.keys(m).sort()) {
  const v = m[k];
  if (typeof v === "function") console.log(k+"()");
  else if (v && typeof v === "object" && v.type) console.log(k+" {"+Object.keys(v).sort().join(", ")+"}");
  else console.log(k+" = "+JSON.stringify(Array.isArray(v)?v.map(x=>x.type):v));
}'
```

which prints exactly:

```
BASIC {buildAuthorizationRest(), buildWWWAuthenticateRest(), computeHash(), decodeHash(), parseAuthorizationRest(), parseWWWAuthenticateRest(), type="Basic"}
```

The Go side was enumerated with `GOWORK=off go doc -all ./httpauth` in the

## Port fixes this harness produced

| case | before | after |
| --- | --- | --- |
| `digest-parse-missing-realm` | `ParseDigest` accepted a credential with no `realm`, then hashed `realm=""` into HA1 | `realm` joins username/nonce/uri/response as REQUIRED (RFC 7616 §3.4), matching upstream and `passport-http` |
| `basic-parse-tab-separator` | HTAB accepted as the scheme/credentials separator | RFC 7235 §2.1 spells the separator `1*SP`; HTAB is now `ErrMalformed`, removing a parser differential with fronting proxies |

## Deviations

All 31 are listed in `parity.json → deviationCases` with the reason on each case,
and summarised in `passport/API-DEVIATIONS.md`. They fall into four families:

1. **Quoting/hardening (7)** — the port renders caller-supplied realms and nonces
   as RFC 7230 quoted-strings; upstream interpolates them raw, so a quote or CRLF
   escapes the header value. Copying upstream here would import an injection.
2. **RFC 7616 vs RFC 2617 (11)** — `-sess` algorithms, `qop=auth-int`, the
   qop-less RFC 2069 digest, `charset`, `userhash`, extension auth-params: the
   port implements the current RFC, upstream the 1999 one.
3. **Grammar strictness (7)** — case-insensitive scheme tokens, BWS around `=`,
   quoted-pair unescaping, a missing `:` in a Basic payload, invalid base64, a
   surplus SP kept inside a token. Upstream's own source calls its parser a
   "FIXME: Create a real parser".
4. **Renderer vs validator (6)** — `*Challenge` and `Encode*` are pure
   formatters; upstream's builders validate required keys and throw. No
   credential decision is taken on either side.
