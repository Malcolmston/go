# `lucene` — API coverage vs Apache Lucene

- **Upstream oracle:** `org.apache.lucene:lucene-core:9.11.1`, plus
  `lucene-analysis-common:9.11.1` and `lucene-queryparser:9.11.1`, pinned in
  `java/pom.xml`. The runner indexes into a `ByteBuffersDirectory`, so no bytes
  ever touch disk on either side.
- **Go port:** `github.com/malcolmston/lucene v0.0.0-20260810111545-f6877e274658`
  (resolved by `GOWORK=off go get github.com/malcolmston/lucene@latest`).
- **Score:** 237 cases, 179 match, 58 mismatch, 0 deviations — **75.53 %**
  (`parity.json`, regenerated by `GOWORK=off go test ./parity/lucene/`).

## How the two inventories were derived

Upstream, mechanically from the pinned jars in `~/.m2`:

```sh
unzip -l lucene-core-9.11.1.jar '*.class'            | grep -c '\.class'   # 2504
unzip -l lucene-analysis-common-9.11.1.jar '*.class' | grep -c '\.class'   #  631
unzip -l lucene-queryparser-9.11.1.jar '*.class'     | grep -c '\.class'   #  250
unzip -l lucene-core-9.11.1.jar 'org/apache/lucene/search/*.class' \
  | grep -o 'search/[A-Za-z0-9_]*\.class' | sort -u | wc -l               #  190
unzip -l lucene-analysis-common-9.11.1.jar '*.class' \
  | grep -o '[A-Za-z0-9_]*Filter\.class' | sort -u | wc -l                #  122 token filters
unzip -l lucene-analysis-common-9.11.1.jar '*.class' \
  | grep -o '[A-Za-z0-9_]*Analyzer\.class' | sort -u | wc -l              #   50 analyzers
```

The port, mechanically: `GOWORK=off go doc -all github.com/malcolmston/lucene`
— 17 functions, 22 types.

**Read the percentage with that asymmetry in mind.** Apache Lucene ships ~3 385
class files across the three pinned artifacts; the port exports 39 symbols. No
honest reading of "75 %" can mean "three quarters of Lucene". The score is
computed **only over the symbols listed in the tables below**, i.e. only where
the port claims to do something Lucene also does. Everything Lucene has that the
port does not attempt is inventoried in "Areas the port does not have" and is
excluded from the denominator rather than counted as a failure.

## What is compared, and what deliberately is not

- **Analyzer token streams** are compared **exactly**: the ordered token list,
  and for the `analyzePositions` cases the `position:token` pair derived from
  `PositionIncrementAttribute`. This is the group where two implementations are
  genuinely commensurable, and it is where most of the real divergence lives.
- **Query semantics** are compared as **(a) the number of matching documents,
  (b) the result SET of doc ids, and (c) the ranked ORDER of doc ids** with
  equal-scoring ids sorted inside their tie (`Searches.ranked`, `hits()` in
  `go/dispatch.go`).
- **Numeric BM25 scores are never compared and never emitted.** Two independent
  BM25 implementations differ in length normalisation, IDF smoothing and float
  rounding; comparing the numbers would produce noise, not evidence. Ranked order
  is the observable that actually matters to a caller.
- Both sides index the identical corpus from `fixtures/corpus.json`, into two
  indexes: `stop` (tokenize + lowercase + stop words) and `standard` (the same
  plus stemming).
- Errors are cases too: parity means *both* sides fail, and message text is not
  compared.

### The port's stemmer is not Porter — confirmed

`an-porter-*` compares `StandardTokenizer+LowerCaseFilter+PorterStemFilter`
against `NewAnalyzer(WithStemming(true))`. 13 of 14 cases diverge:

| input | Lucene `PorterStemFilter` | port | what the port does wrong |
| --- | --- | --- | --- |
| `Runners` | `runner` | `runn` | strips `-er` unconditionally, then `-s`; Porter's step 4 requires `m>1` |
| `runner writer actor teacher other` | `runner writer actor teacher other` | `runn writ act teach oth` | strips `-er`/`-or` unconditionally at `m>0`; Porter does not strip them at all here |
| `documents documentation` | `document document` | `docu documentation` | truncates to `docu`; leaves `documentation` untouched |
| `agreed plastered motoring` | `agre plaster motor` | `agree plast mot` | step 1b is applied with the wrong measure |
| `happy skies` | `happi ski` | `happy ski` | **step 1c (`y`→`i`) is absent** |
| `relational conditional rational` | `relat condit ration` | `relat condition rational` | **step 2 suffix map is largely absent** |
| `formative electricity` | `form electr` | `format electric` | **step 3 is largely absent** |
| `revival homologou` | `reviv homolog` | `revival homologou` | **step 4 is largely absent** |
| `cease controll` | `ceas control` | `cease controll` | **step 5a/5b (final `e`, double `l`) are absent** |
| `easily only really useful` | `easili onli realli us` | `easi on real use` | `-ly`/`-ful` handled ad hoc |
| `library` | `librari` | `library` | never applied — the port leaves words of ≤4 runes, and many others, untouched |
| `conflated sized hopping tanned falling hissing fizzed` | `conflat size hop tan fall hiss fizz` | same | the one matching case |

The consequence is visible in the term dictionary: `ix-terms-text-standard`
diverges on 11 of 53 positions (`answer/answ`, `color/col`, `document/docu`,
`languag`… vs `library`, `memori` vs `memory`, `runner` vs `runn`, `retriev` vs
`retrieval`, `tabl` vs `table`). Both engines remain *self-consistent* — a query
term is stemmed with the same stemmer that indexed the corpus — so most searches
still agree (`q-std-term-documents`, `q-std-term-running`, `q-std-phrase` all
match). It breaks where Porter's conflation is the whole point:
`q-std-term-documentation` finds 2 docs upstream and 0 in the port.

**The most valuable finding in this harness:** of the 17 parser mismatches, 11
are *silent* — the port returns a perfectly ordinary, successful result for a
query whose meaning it did not understand. `search AND library`,
`search NOT library`, `search^3`, `netwrk~1`, `n?twork` and `*work` all parse
without error and answer the wrong question. A caller has no signal that
anything went wrong. By contrast the port's constructor API for the same
operations (`NewFuzzyQuery`, `NewWildcardQuery`, `NewBoostQuery`, `MustNot`) is
largely at parity — the weakness is in the parser, not the query engine.

## Areas the port does not have at all

These are excluded from the score rather than counted as failures.

- **Persistence — confirmed absent.** The port is purely in-memory: `NewIndex`
  takes only an `Analyzer`, there is no `Directory`, no `IndexWriter`/
  `IndexWriterConfig`, no `commit`, no `Codec`, no segment files, no
  `DirectoryReader.open(path)`, no way to reopen an index in a new process.
  Upstream ships `BaseDirectory`, `ByteBuffersDirectory`, `FSDirectory`,
  `MMapDirectory`, `NIOFSDirectory`, `NRTCachingDirectory`, `FileSwitchDirectory`,
  `FilterDirectory`, the whole `org.apache.lucene.codecs` tree, and the
  transactional `IndexWriter`/`SegmentInfos` machinery. **None of it is ported.**
  Restarting a process loses the entire index.
- **Segments and merging:** `MergePolicy`, `TieredMergePolicy`, `MergeScheduler`,
  `forceMerge`, `addIndexes`, `IndexUpgrader`, `CheckIndex`.
- **Concurrency and near-real-time search:** `SearcherManager`,
  `ReferenceManager`, `ControlledRealTimeReopenThread`,
  `DirectoryReader.openIfChanged`, per-segment `LeafReader` search,
  `TaskExecutor`-based intra-query parallelism.
- **Field types:** only `map[string]string` text fields. No `StringField`,
  `StoredField`, `IntPoint`/`LongPoint`/`DoublePoint`, `SortedDocValues`,
  `NumericDocValues`, `BinaryDocValues`, `LatLonPoint`, `KnnFloatVectorField`,
  `Field.TermVector`, term vectors, norms control, or per-field analyzers
  (`PerFieldAnalyzerWrapper`).
- **Vector / KNN search:** the entire HNSW stack (`KnnFloatVectorQuery`,
  `VectorSimilarityFunction`, `Lucene99HnswVectorsFormat`).
- **Sorting, collecting and explaining:** `Sort`, `SortField`, `FieldComparator`,
  `Collector`, `CollectorManager`, `TopFieldCollector`, `searchAfter`,
  `Explanation`/`explain`, `QueryRescorer`, `LRUQueryCache`.
- **Pluggable scoring:** `Similarity` and its ~8 implementations; the port's BM25
  is hard-wired with fixed `k1`/`b`.
- **Span and interval queries:** `org.apache.lucene.queries.spans.*`,
  `org.apache.lucene.queries.intervals.*`.
- **Grouping, joining, faceting, highlighting, monitoring, spatial, suggest,
  replicator, luke** — every satellite module.
- **Query rewriting:** `MultiTermQuery.RewriteMethod`, the
  `CONSTANT_SCORE_BLENDED_REWRITE` behaviour that makes `q-prefix-ranked`
  diverge, `IndexSearcher.rewrite`, `QueryVisitor`.
- **Alternative parsers:** `MultiFieldQueryParser`,
  `ComplexPhraseQueryParser`, `SimpleQueryParser`, the flexible
  `StandardQueryParser`, `surround`, `xml`.

## Reproducing

```sh
cd parity/lucene/java && mvn -q package          # pins lucene-core 9.11.1
cd .. && GOWORK=off go test ./parity/lucene/     # from the repo root
```

The suite `t.Skip`s (never fails) when `java` or `mvn` is absent, or when Maven
can neither build offline from `~/.m2` nor fetch the pinned artifacts.
