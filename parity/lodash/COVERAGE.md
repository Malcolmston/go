# COVERAGE — `lodash` (Go port) vs `lodash@4.17.21`

Every row in the first table is one **exported symbol of the installed upstream
package**. The list is derived mechanically from the pinned install, never from
the README or from memory:

```
cd parity/lodash/node
npm install lodash@4.17.21          # already pinned in node/package.json
node -e "console.log(Object.keys(require('lodash')).sort().join('\n'))"
```

That yields **308 exports** (including the two non-function exports `VERSION`
and `_`). The Go side of each row comes from

```
cd parity/lodash
GOWORK=off go doc -all github.com/malcolmston/lodash
```

against `github.com/malcolmston/lodash v0.0.0-20260810111543-820ef3866dc9`,
which exports **296 top-level functions** and **12 top-level types**.

Statuses:

- `match` — every case for the symbol agreed with upstream.
- `differs` — at least one case disagreed. The note says whether it is a real
  mismatch or a **deliberate deviation** (a difference forced by Go's type
  system, marked `"deviation"` in the case file; those must also be listed in
  the library's own `API-DEVIATIONS.md`, which lives outside this directory).
- `missing` — the upstream symbol has no counterpart in the port.
- `untested` — a counterpart exists but no case exercises it. A symbol with no
  case is never `match`.
- `extra` — Go-only surface with no upstream symbol.

## Deliberate deviations (22 cases, kept and marked, not counted as matches)

Each of these is forced by Go's type system or is documented Go behaviour, so
the case carries a `"deviation"` reason instead of failing the suite. They still
need listing in the library's own `API-DEVIATIONS.md`, which is outside this
directory.

| root cause | cases |
| --- | --- |
| **`Compact` drops the zero value of `T`, not JS-falsy values.** With `T = any` only `nil` is the zero value, so `0`, `""`, `false` and `NaN` survive. JS falsiness over a dynamically typed element is not expressible generically. | `compact-mixed`, `compact-all-falsy`, `compact-nan`, `compact-nested-empty`, `seqSet-compact-without` |
| **Go has no `undefined`.** Missing elements, absent keys and never-called wrappers all collapse onto `nil`/the zero value. | `zipObject-short-values`, `at-missing`, `before-1`, `isNull-undefined`, `isUndefined-null`, `assignWith-add`, `mergeWith-add` |
| **`DefaultTo` falls back on the zero value of `T`** (documented), where lodash falls back only for `null`, `undefined` and `NaN`. | `defaultTo-zero`, `defaultTo-empty-string`, `defaultTo-nan` |
| **Different function shape.** `Zip` truncates to the shorter input (documented); `UnzipWith` folds each `Pair` rather than each column; `CastArray` is variadic and always wraps; `Transform` is a pure fold while lodash's mutates an accumulator. | `zip-unequal`, `unzipWith-add`, `castArray-array`, `transform-sum` |
| **`Merge` is documented as shallow** (later maps override); `DefaultsDeep` is the deep counterpart. | `merge-nested` |
| **`IsMap` asks "is this a Go map"**, lodash asks "is this a JS `Map`". | `isMap-object` |
| **`Template` embeds no scripting engine** (documented), so an unresolvable path renders empty where lodash throws a `ReferenceError`. | `template-missing` |

## What is deliberately not tested

- `debounce`, `throttle`, `defer`, `delay` — timing-dependent; the harness must
  be deterministic, so their Go counterparts (`NewDebouncer`, `NewThrottler`,
  `Defer`, `Delay`) carry no cases.
- `_.invert` with colliding values — lodash keeps the last key in insertion
  order, Go map iteration is randomised, so no deterministic case exists.
- `sample`, `sampleSize`, `shuffle` and `random` are tested through an
  invariant (membership / size / permutation / bounds) rather than the draw.

## How the two sides are made comparable

- Results that Go produces in randomised map order (`keys`, `values`,
  `toPairs`, `entries`, `mapToSlice`, `filterMap`, `rejectMap`, `forOwn`,
  `partitionMap`, `groupByMap`, `invertBy`) are **sorted on both sides** before
  emission, in both runners.
- Object keys are emitted sorted (Node sorts explicitly, Go's `encoding/json`
  sorts `map[string]any` keys already).
- Values JSON cannot carry are encoded identically by both runners:
  `{"$undefined":true}`, `{"$nan":true}`, `{"$inf":±1}`, `{"$date":"<ISO>"}`,
  `{"$regexp":"<source>"}`, `{"$function":true}`.
- Callables in a case are named references — `{"$fn":"isEven"}` — resolved from
  a registry defined identically in both runners. Every entry is a factory, so
  stateful helpers (e.g. `counter`, used to observe `once`/`after`/`memoize`)
  start fresh per case.
- lodash functions that *return* functions are exercised by a composite op: the
  case supplies a list of argument lists and the op returns the list of results.
