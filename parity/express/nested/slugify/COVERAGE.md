# `express/slugify` vs `slugify` — API coverage

- **Upstream (oracle):** `slugify@1.6.9` (simov/slugify), pinned in `node/package.json`.
- **Port:** `github.com/malcolmston/express/slugify` (local submodule via the
  `replace` in `go.mod`).
- **Score:** see `parity.json`, regenerated by `GOWORK=off go test .`.

## How the upstream inventory was derived

Mechanically, from the installed package rather than from the README:

```sh
cd node && npm install
node --input-type=module -e '
  import slugify from "slugify";
  console.log(Object.keys(await import("slugify")));   // namespace keys
  console.log(typeof slugify, slugify.length);          // callable + arity
  console.log(Object.keys(slugify));                    // own properties
'
# => namespace ["default","module.exports"]
# => function 2
# => ["extend","default"]
```

The option keys are not reflectable (they are destructured inside the function),
so they were read off the installed implementation itself, which is the same
artefact the oracle runs:

```sh
grep -n "options\." node/node_modules/slugify/slugify.js
# => options.locale, options.replacement, options.trim, options.remove,
#    options.strict, options.lower
```

The transliteration table was likewise compared entry by entry against the
installed `charMap`, not by eye:

```sh
node -e 'const s=require("fs").readFileSync("node/node_modules/slugify/slugify.js","utf8");
         const m=s.match(/var charMap = JSON\.parse\(.(.*?).\)\n/s);
         console.log(Object.keys(JSON.parse(m[1].replace(/\\./g,"'"'"'"))).length)'
# => 641 entries, matching the port's charMap size exactly
```

## How the score is counted

`parity.json` separates three outcomes, and `go test` fails only on the middle
one:

- **match** — both implementations gave the same answer (or both failed).
- **mismatch** — they differed and the difference is *not* declared. This is a
  bug in the port; the harness reports it with `t.Errorf`.
- **deviations** — they differed and the case carries a `"deviation"` tag
  explaining why, which is also listed in the express submodule's
  `API-DEVIATIONS.md`. `../../../HARNESS.md` requires these to be counted
  separately from a bug, so they are excluded from `compared` and reported with
  `t.Logf`. `declaredDeviations` counts the tags; if it ever exceeds
  `deviations`, `staleDeviations` names the tags that describe a difference which
  no longer happens and should be deleted.

`parityPercent` is `match / compared`, i.e. over the cases where the two
implementations are expected to agree.

### Message-text differences

Never compared (per `../../../HARNESS.md`), recorded here instead: upstream
throws `Error("slugify: string argument expected")`; the Go port cannot be handed
a non-string at all, so the runner reports the same condition without a message.

## Declared deviations

Each is also listed in the express submodule's `API-DEVIATIONS.md`.

1. `opt-replacement-empty` — `Options.Separator` is a plain `string` whose zero
   value is indistinguishable from "unset", so `Separator: ""` falls back to
   `"-"`. Upstream defaults only when the key is `undefined`, so
   `slugify("Hello Big World", {replacement: ""})` is `"HelloBigWorld"` there.
2. `charmap-dev-e-ogonek`, `charmap-dev-i-macron`, `charmap-dev-k-cedilla`,
   `charmap-dev-u-macron` — `Ę`, `Ī`, `Ķ` and `Ū`. The port tracks
   simov/slugify **master**, whose `charmap.json` spells these four upper-case;
   the pinned 1.6.9 release still carries the lower-case values (`"e"`, `"i"`,
   `"k"`, `"u"`), which upstream's own Latvian/Polish tests contradict. The
   port's in-repo vectors are extracted from master, so changing them would
   break a test suite that is closer to upstream's intent than the release is.

## Untested

| surface | why |
| --- | --- |
| `options.locale` | not ported (`missing`); a case would compare a feature only one side has |
| `slugify.extend` | not ported (`missing`); it mutates a module-global table |
| NFC normalisation | upstream calls `String.prototype.normalize()` before mapping. Every input that could distinguish it (decomposed `Crème Brûlée`, `Å`) produces the same slug either way, because the stray combining mark is removed by the same pattern that would have been applied after composing. `uni-decomposed-nfd` keeps the case; there is no observed difference to report |
