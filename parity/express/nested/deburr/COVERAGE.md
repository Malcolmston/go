# `express/deburr` vs lodash `deburr` — API coverage

- **Upstream (oracle):** `lodash@4.17.21`, its `deburr` method
  (`require("lodash/deburr.js")`), pinned in `node/package.json`.
- **Port:** `github.com/malcolmston/express/deburr`.
- **Score:** see `parity.json`, regenerated by `GOWORK=off go test .`.

## Why `lodash@4.17.21` and not `lodash.deburr@4.1.0`

The per-method package was tried first. `lodash.deburr@4.1.0` is a 2016 snapshot
that upstream has since fixed twice, and both fixes matter here:

```sh
grep -n "ComboMarks\|rsComboSymbols" node_modules/lodash.deburr/index.js
# var rsComboMarksRange = '̀-ͯ︠-︣',
#     rsComboSymbolsRange = '⃐-⃰';
grep -n "u017f" node_modules/lodash.deburr/index.js
# 'ŉ': "'n", 'ſ': 'ss'
```

versus current lodash, whose ranges are `̀-ͯ︠-︯` and
`⃐-⃿`, and whose `ſ` maps to `'s'`. Measured:

```sh
node -e 'const d = require("lodash/deburr.js");
         console.log(JSON.stringify(d("ſ")), JSON.stringify(d("a⃟b")))'
# => "s" "ab"       (lodash@4.17.21)
# => "ss" "a⃟b"     (lodash.deburr@4.1.0)
```

The port matches 4.17.21 on both, so scoring against the frozen standalone would
have reported two "failures" that are upstream bugs already fixed. The maintained
`lodash` package is the real upstream of "lodash's deburr utility", which is what
the port's doc comment claims to port, so that is the pinned oracle.

## How the upstream inventory was derived

```sh
cd node && npm install
node -e 'const d = require("lodash/deburr.js");
         console.log(typeof d, d.length, JSON.stringify(Object.keys(d)))'
# => function 1 []
```

One function, one argument, no properties: the whole API surface is `deburr` plus
its two internal tables, which are enumerated by the `perchar` and `combining`
case groups character by character.

## How the score is counted

`parity.json` separates three outcomes, and `go test` fails only on the middle
one:

- **match** — both implementations gave the same answer (or both failed).
- **mismatch** — they differed and the difference is *not* declared. This is a
  bug in the port; the harness reports it with `t.Errorf`.
- **deviations** — they differed and the case carries a `"deviation"` tag
  explaining why, which is also listed in the express submodule's
  `API-DEVIATIONS.md`. `../../../HARNESS.md` requires these to be counted
  separately from a bug, so they are excluded from `compared` and reported with
  `t.Logf`. `declaredDeviations` counts the tags; if it ever exceeds
  `deviations`, `staleDeviations` names the tags that describe a difference which
  no longer happens and should be deleted.

`parityPercent` is `match / compared`, i.e. over the cases where the two
implementations are expected to agree.

## What the harness fixed

4 of 81 cases failed at first run. `isComboMark` stripped the Combining
Diacritical Marks **Extended** (U+1AB0–U+1AFF) and **Supplement**
(U+1DC0–U+1DFF) blocks. lodash defines those ranges for its Unicode word
splitter but `deburr`'s regexp does not use them, so `_.deburr` leaves those
marks in place. The two ranges were removed from the port and the package doc
comment, which listed them, was corrected.
