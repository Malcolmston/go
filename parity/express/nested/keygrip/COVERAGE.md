# `keygrip` → `github.com/malcolmston/express/keygrip`

Upstream oracle: **keygrip@1.1.0** (crypto-utils/keygrip, pinned in
`node/package.json`). Measured score: `parity.json` — regenerated by
`GOWORK=off go test .`.

## How the upstream inventory was derived

Mechanically, from the installed package — the constructor's own properties and
the properties a constructed instance carries:

```sh
node -e "const K=require('keygrip');
  console.log('static:', Object.keys(K).join(' '));
  console.log('instance:', Object.keys(K(['a','b'])).join(' '));
  console.log('arity:', K.length)"
```

```
static:   index verify sign
instance: sign verify index
arity:    3
```

The three *static* properties are deliberate tripwires, not API:
`Keygrip.sign = Keygrip.verify = Keygrip.index = function() { throw new
Error("Usage: require('keygrip')(<array-of-keys>)") }`. The constructor's arity
of 3 is `(keys, algorithm, encoding)`.

## Declared deviation

`keygrip(keys)` defaults to **HMAC-SHA1**; `keygrip.New(keys)` defaults to
**HMAC-SHA256**. Changing the port's default to SHA-1 would weaken every existing
caller and silently invalidate every cookie already signed with SHA-256, so the
default stands and the difference is declared: cases `sign-default-scheme` and
`verify-default-scheme` carry a `deviation` string and are counted separately
from bugs. Interoperating with a Node service that relies on the upstream default
is a one-line change — `NewWithOptions(keys, Options{Algorithm: "sha1"})` — and
`sign-sha1` proves it produces the identical digest.

## Before → after

Measured on this same corpus with the pre-fix API (no `NewWithOptions`, so the
algorithm and encoding arguments could not be expressed at all):
**49/63 = 77.78% → 63/63 = 100%**. The 14 cases that changed are the ten
non-default algorithm/encoding cases plus the four
unknown-algorithm/unknown-encoding failures, which the port previously ignored
instead of rejecting.

## What the cases establish

- **Rotation is the feature, and it is measured.** `index-current-key`,
  `index-previous-key` and `index-oldest-key` each present a digest produced by a
  different key in the list and assert the index the port reports; the retired
  key (`verify-retired-key`) must be refused, and dropping a key from the list
  must stop its digests verifying (`verify-single-key-list-old-digest`).
- **Every digest in the `verify` group was produced by the pinned upstream**, so
  the accepting cases are cross-implementation verification rather than the port
  agreeing with itself.
- **The rejection corpus.** Tampered data, a flipped digest character, truncated
  and extended digests, a `=`-padded digest, a standard-base64 (`+`/`/`) digest, a
  digest computed under a different hash, a digest in a different encoding, and a
  digest for different data all fail on both sides.
