# `express/kebabcase` vs `change-case` (`kebabCase`) — API coverage

- **Upstream (oracle):** `change-case@5.4.4` (blakeembrey/change-case), the
  `kebabCase` export, pinned in `node/package.json`.
- **Port:** `github.com/malcolmston/express/kebabcase`.
- **Score:** see `parity.json`, regenerated by `GOWORK=off go test .`.

## Why change-case is the oracle

The package doc comment used to name npm `kebab-case`, so that package was
evaluated first. It is not what the port implements. `kebab-case@2.0.2` is five
lines:

```sh
cat node_modules/kebab-case/index.js   # in a scratch install
# const KEBAB_REGEX = /\p{Lu}/gu;
# const kebabCase = (str, keepLeadingDash = true) => {
#   const result = str.replace(KEBAB_REGEX, (m) => `-${m.toLowerCase()}`);
#   ...
# };
node --input-type=module -e 'import k from "kebab-case";
  console.log(k("fooBar Baz"), "|", k("XMLHttpRequest"), "|", k("FOO"))'
# => "foo-bar -baz" | "-x-m-l-http-request" | "-f-o-o"
```

It does not treat spaces or underscores as separators, does not trim, does not
collapse runs, and prefixes a dash to every capital. lodash's `kebabCase` is
closer but deburrs its input (`Crème Brûlée` → `creme-brulee`).

What the port actually implements is change-case's `split` + lower + join:
separator collapsing, end trimming, case-transition boundaries, no deburring
(`Crème Brûlée` → `crème-brûlée`). The evidence is in the port itself — its
in-repo vector file `kebabcase_parity_test.go` is extracted from
`blakeembrey/change-case`'s `index.spec.ts`, and the code comment on the
separator rule cites "the upstream change-case strip regexp `/[^\p{L}\d]+/`".
So change-case is the oracle, and the package doc comment has been corrected to
say so.

## How the upstream inventory was derived

```sh
cd node && npm install
node --input-type=module -e '
  const ns = await import("change-case");
  for (const k of Object.keys(ns)) console.log(k, typeof ns[k], ns[k].length);
'
# camelCase 2, capitalCase 2, constantCase 2, dotCase 2, kebabCase 2, noCase 2,
# pascalCase 2, pascalSnakeCase 2, pathCase 2, sentenceCase 2, snakeCase 2,
# split 1, splitSeparateNumbers 1, trainCase 2
```

Only `kebabCase` is in scope: the other thirteen exports are different case
conventions, ported (or not) elsewhere in the express submodule. The option keys
were read off the installed implementation, which is the artefact the oracle runs:

```sh
grep -n "options?\." node/node_modules/change-case/dist/index.js
# => options?.delimiter, options?.locale, options?.split,
#    options?.prefixCharacters, options?.suffixCharacters
```

## How the score is counted

`parity.json` separates three outcomes, and `go test` fails only on the middle
one:

- **match** — both implementations gave the same answer (or both failed).
- **mismatch** — they differed and the difference is *not* declared. This is a
  bug in the port; the harness reports it with `t.Errorf`.
- **deviations** — they differed and the case carries a `"deviation"` tag
  explaining why, which is also listed in the express submodule's
  `API-DEVIATIONS.md`. `../../../HARNESS.md` requires these to be counted
  separately from a bug, so they are excluded from `compared` and reported with
  `t.Logf`. `declaredDeviations` counts the tags; if it ever exceeds
  `deviations`, `staleDeviations` names the tags that describe a difference which
  no longer happens and should be deleted.

`parityPercent` is `match / compared`, i.e. over the cases where the two
implementations are expected to agree.

## Untested

| surface | why |
| --- | --- |
| `options.delimiter` / `locale` / `split` / `prefixCharacters` / `suffixCharacters` | not ported (`missing`); a case would compare a feature only one side has |

| `String.prototype.trim` at U+0085 / U+FEFF | JavaScript's `trim` strips U+FEFF but not U+0085; Go's `TrimSpace` does the opposite. Neither can be observed through `KebabCase`, because both characters are non-word characters that the strip pass collapses into a boundary and the boundary trim then removes. There is no input that distinguishes them, so no case was invented |

## What the harness fixed

18 of 102 cases failed at first run. Two causes, both now fixed in the port:

1. **No acronym rule.** `XMLHttpRequest` → `xmlhttp-request` instead of
   `xml-http-request`; `ABCdef` → `abcdef` instead of `ab-cdef`. `KebabCase` was
   rewritten around change-case's actual two-pass `split`.
2. **Simple instead of full lowercase mapping.** `ΟΔΟΣ` → `οδοσ` instead of
   `οδος`, `İzmir` → `izmir` instead of `i̇zmir`. `casemap.go` adds the two rules
   JavaScript's `toLowerCase` applies.

Two hand-written expectations in the submodule's own `kebabcase_test.go` and
`example_test.go` encoded the old, non-upstream behaviour and were corrected;
the extracted upstream vectors in `kebabcase_parity_test.go` were already
consistent with the fix and needed no change.
