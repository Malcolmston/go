# `cookie-signature` → `github.com/malcolmston/express/cookiesignature`

Upstream oracle: **cookie-signature@1.2.2** (pinned in `node/package.json`).
Measured score: `parity.json` — regenerated by `GOWORK=off go test .`.

## How the upstream inventory was derived

Mechanically, from the installed package:

```sh
node -e "console.log(Object.keys(require('cookie-signature')).sort().join('\n'))"
```

which prints exactly two names:

```
sign
unsign
```

`cookie-signature` has no classes, no options object and no other exports; the
whole module is those two functions (`node/node_modules/cookie-signature/index.js`
is 45 lines).

### Type checks that have no Go equivalent

Upstream throws `TypeError` when `val`/`input` is not a string or when `secret`
is `null`/`undefined`. Both are unrepresentable in Go: `Sign(value, secret
string)` cannot be handed a non-string, and `secret` cannot be nil. They are
therefore not defects and not cases — Go's type system enforces upstream's
runtime checks at compile time. `sign-empty-secret` and
`unsign-roundtrip-empty-secret` cover the one reachable neighbour, an empty (but
present) secret, which upstream also accepts.

## What the cases establish

- **Byte-for-byte interoperability.** Every `unsign-roundtrip-*` input was signed
  by the pinned upstream and is accepted by the Go port, and every `sign-*` case
  compares the exact string the two implementations produce. A cookie signed by
  a Node service unsigns here and vice versa.
- **The rejection corpus is the point.** 17 of the 29 `unsign` cases are
  forgeries or malformed inputs — a tampered value under a genuine signature, a
  privilege flag flipped, a signature truncated, extended, `=`-padded,
  case-flipped or re-encoded into the base64url alphabet, a genuine signature
  attached to a different value, the value and secret swapped, and inputs with
  no separator at all. All must fail on both sides, and do.
- **The dot is not a delimiter of the value.** `unsign-roundtrip-dots` and
  `unsign-roundtrip-many-dots` pin the "split on the LAST dot" rule, which is
  what lets a signed cookie value contain dots.
- **Determinism.** No clock, no key generation, no randomness: `sign` is a pure
  function of `(value, secret)` on both sides.
