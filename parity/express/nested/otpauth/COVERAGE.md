## How the upstream inventory was derived

Mechanically, by reflecting over the installed CommonJS build:

```sh
node -e "const o=require('otpauth');
  console.log('module:', Object.keys(o).sort().join(' '));
  for (const n of ['HOTP','TOTP','URI','Secret'])
    console.log(n, 'static:', Object.getOwnPropertyNames(o[n]).join(' '),
                '| proto:', Object.getOwnPropertyNames(o[n].prototype).join(' '));
  const t=new o.TOTP({secret:o.Secret.fromBase32('JBSWY3DPEHPK3PXP')});
  console.log('TOTP instance:', Object.keys(t).join(' '));
  console.log('defaults:', JSON.stringify(o.TOTP.defaults), JSON.stringify(o.HOTP.defaults))"
```

`length`, `name` and `prototype` are function intrinsics, not API, and are not
counted below.

The port takes a different shape: one `Config` struct with methods, rather than
HOTP/TOTP classes. The mapping below is therefore per *operation*.

## Before → after

**122/158 = 77.22% → 158/158 = 100%.** The 36 cases that changed, and the fixes
behind them:

1. **URI rendering** (17 cases: all `uri-*` and `roundtrip-*`). `URL` now escapes
   components exactly as `encodeURIComponent` does (`%40` for `@`, `%20` for a
   space, `!'()*-._~` untouched), always writes `algorithm`, `digits` and
   `period`/`counter` rather than omitting defaults, canonicalises the secret, and
   honours `OmitIssuerFromLabel`.
2. **URI parsing** (11 cases). `Parse` now rejects what upstream rejects — an
   unknown type, a missing or non-base32 secret, an HOTP URI with no counter, a
   non-positive `digits` or `period`, an unknown algorithm, an empty label, a URI
   with no query — and fills in the scheme's defaults for absent parameters.
   Query parsing no longer turns `+` into a space, since `decodeURIComponent`
   does not.
3. **Digit counts past ten** (1 case). A code longer than ten digits is now
   zero-padded, as upstream's `padStart` does, instead of being clamped.
4. **SHA-224 and SHA-384** (2 cases), added to the algorithm table.
5. Plus the 5 round-trip cases that depend on (1) and (2) together.

## Declared deviations

| case | deviation |
| --- | --- |
| `gen-empty-secret`, `secret-empty` | upstream HMACs a zero-length key for an empty secret; `DecodeSecret` returns `ErrInvalidSecret` |
| `gen-single-char-secret`, `secret-single-char`, `secret-nine-chars` | upstream silently discards a partial base32 byte; the port rejects an incomplete block |
| `gen-sha3-algorithm` | SHA-3 is outside the Go standard library, so the SHA3-* algorithms the URI scheme permits can be parsed but not computed |

## What the cases establish

- **The RFC vectors, on both sides.** RFC 4226 appendix D (counters 0, 1, 5, 9)
  and RFC 6238 appendix B (T=59, 1111111109, 1234567890, 2000000000 across
  SHA1/SHA256/SHA512) are computed by both implementations from the same fixed
  secret and compared.
- **Nothing reads the clock.** Every TOTP case carries an explicit millisecond
  timestamp and every HOTP case an explicit counter.
- **The window is measured, not assumed.** `val-totp-previous-step`,
  `val-totp-next-step`, `val-totp-far-inside-wide-window` pin the returned delta;
  `val-totp-previous-step-zero-window`, `val-totp-next-step-zero-window` and
  `val-totp-far-outside-window` pin the refusals. `val-totp-default-window`
  checks that both sides default the window to 1.
- **Cross-parameter forgeries fail.** A code generated with a different period,
  a different algorithm, a different secret, or a different digit count is
  rejected, as is a TOTP code offered to an HOTP config.
