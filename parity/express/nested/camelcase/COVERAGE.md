# `express/camelcase` vs `camelcase` — API coverage

- **Upstream (oracle):** `camelcase@9.0.0` (sindresorhus/camelcase), pinned in
  `node/package.json`.
- **Port:** `github.com/malcolmston/express/camelcase`.
- **Score:** see `parity.json`, regenerated by `GOWORK=off go test .`.

## How the upstream inventory was derived

Mechanically, from the installed ESM package:

```sh
cd node && npm install
node --input-type=module -e '
  const ns = await import("camelcase");
  console.log(Object.keys(ns));            // ["default"]
  console.log(typeof ns.default, ns.default.length, Object.keys(ns.default));
'
# => ["default"]
# => function 2 []
```

There is exactly one export and it carries no properties, so the API surface is
the function plus its options object. The option keys are destructured inside the
function and therefore not reflectable; they were read off the installed
implementation, which is the artefact the oracle runs:

```sh
grep -n "options\." node/node_modules/camelcase/index.js
# => options.pascalCase, options.preserveConsecutiveUppercase,
#    options.capitalizeAfterNumber, options.locale
```

## How the score is counted

`parity.json` separates three outcomes, and `go test` fails only on the middle
one:

- **match** — both implementations gave the same answer (or both failed).
- **mismatch** — they differed and the difference is *not* declared. This is a
  bug in the port; the harness reports it with `t.Errorf`.
- **deviations** — they differed and the case carries a `"deviation"` tag
  explaining why, which is also listed in the express submodule's
  `API-DEVIATIONS.md`. `../../../HARNESS.md` requires these to be counted
  separately from a bug, so they are excluded from `compared` and reported with
  `t.Logf`. `declaredDeviations` counts the tags; if it ever exceeds
  `deviations`, `staleDeviations` names the tags that describe a difference which
  no longer happens and should be deleted.

`parityPercent` is `match / compared`, i.e. over the cases where the two
implementations are expected to agree.

### Message-text differences

Upstream throws ``TypeError("Expected the input to be `string | string[]`")``.
The Go signature accepts only `string`, so the condition cannot arise and no case
compares it.

## What the harness fixed

The `case-mapping` group was added because JavaScript's `toLowerCase` /
`toUpperCase` implement Unicode's **full** case mappings while Go's standard
library only offers the **simple** per-rune mapping. 21 of 260 cases failed on
that difference: `ß` → `SS`, `ﬁ` → `FI`, `ﬄ` → `FFL`, `ŉ` → `ʼN`, `ǰ` → `J̌`,
`ΐ` → `Ϊ́`, the Turkish `İ` → `i` + U+0307, and Greek final sigma. The port now
carries `casemap.go`, whose 102-entry expansion table is generated from the
JavaScript engine itself (the command is in the file header) plus the two rules
that are contextual rather than tabular.
