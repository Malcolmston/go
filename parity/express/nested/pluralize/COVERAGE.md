# `express/pluralize` vs `pluralize` — API coverage

- **Upstream (oracle):** `pluralize@8.0.0` (plurals/pluralize), pinned in
  `node/package.json`. 8.0.0 is the newest published release.
- **Port:** `github.com/malcolmston/express/pluralize`.
- **Score:** see `parity.json`, regenerated by `GOWORK=off go test .`.

## How the upstream inventory was derived

Mechanically, by reflecting over the installed package:

```sh
cd node && npm install
node -e 'const p = require("pluralize");
         console.log(typeof p, p.length);
         console.log(Object.keys(p))'
# => function 3
# => ["plural","isPlural","singular","isSingular",
#     "addPluralRule","addSingularRule","addUncountableRule","addIrregularRule"]
```

The three rule tables were diffed against the port's, again from the installed
file rather than from memory:

```sh
sed -n '/Irregular rules/,/addIrregularRule/p'   node/node_modules/pluralize/pluralize.js
sed -n '/Pluralization rules/,/addPluralRule/p'  node/node_modules/pluralize/pluralize.js
sed -n '/Singularization rules/,/addSingularRule/p' node/node_modules/pluralize/pluralize.js
sed -n '/Uncountable rules/,/addUncountableRule/p'  node/node_modules/pluralize/pluralize.js
```

## How the score is counted

`parity.json` separates three outcomes, and `go test` fails only on the middle
one:

- **match** — both implementations gave the same answer (or both failed).
- **mismatch** — they differed and the difference is *not* declared. This is a
  bug in the port; the harness reports it with `t.Errorf`.
- **deviations** — they differed and the case carries a `"deviation"` tag
  explaining why, which is also listed in the express submodule's
  `API-DEVIATIONS.md`. `../../../HARNESS.md` requires these to be counted
  separately from a bug, so they are excluded from `compared` and reported with
  `t.Logf`. `declaredDeviations` counts the tags; if it ever exceeds
  `deviations`, `staleDeviations` names the tags that describe a difference which
  no longer happens and should be deleted.

`parityPercent` is `match / compared`, i.e. over the cases where the two
implementations are expected to agree.

None: neither side raises for any input in the suite. Both return the input

## Declared deviations

The port was transcribed from plurals/pluralize **master**, which is ahead of the
last published release (8.0.0, 2019). Every difference the harness finds is that
gap, and each is listed in the express submodule's `API-DEVIATIONS.md`. Because
npm carries no publish of master, the oracle has to be 8.0.0 — an unpinnable
oracle would make the score unreproducible.

| case(s) | difference |
| --- | --- |
| `pl-057-canvas`, `sg-057-canvases` | master adds the irregular pair `canvas`/`canvases`; 8.0.0 falls through to the rules and yields `canvas` / `canvase` |
| `sg-103-cookies`, `sg-105-calories`, `sg-106-hippies` | master widened the `-ies` stem rules (`(…|ok|…)ies → $1ie` and a longer `\b(…|hipp|…|calor|…)ies` alternation); 8.0.0 falls through to `ies$ → y` and produces `cooky`, `calory`, `hippy` |
| `unc-005-species-sg` | master drops `species` from the uncountable list, so it singularises to `specie`; 8.0.0 keeps it uncountable |
| `devi-my-*`, `devi-his-*`, `devi-her-*`, `devi-its-*` | master adds the possessive-pronoun irregular pairs `my`/`our`, `his`/`their`, `her`/`their`, `its`/`their`; 8.0.0 has none of them, so it applies the regular rules (`my` → `mies`, `his` → `hi`, …) |
