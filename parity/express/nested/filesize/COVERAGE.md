# `express/filesize` vs `filesize` — API coverage

- **Upstream (oracle):** `filesize@11.0.22` (avoidwork/filesize), pinned in
  `node/package.json`.
- **Port:** `github.com/malcolmston/express/filesize`.
- **Score:** see `parity.json`, regenerated by `GOWORK=off go test .`.

## How the upstream inventory was derived

```sh
cd node && npm install
node --input-type=module -e '
  const ns = await import("filesize");
  for (const k of Object.keys(ns)) console.log(k, typeof ns[k], ns[k].length);
'
# filesize function 1
# partial  function 0
```

The option keys are destructured in the signature, so they are read straight off
the installed implementation — the artefact the oracle runs:

```sh
sed -n '/^function filesize(/,/^) {/p' node/node_modules/filesize/dist/filesize.cjs
# bits, pad, base, round, locale, localeOptions, separator, spacer, symbols,
# standard, output, fullform, fullforms, exponent, roundingMethod, precision
```

## How the score is counted

`parity.json` separates three outcomes, and `go test` fails only on the middle
one:

- **match** — both implementations gave the same answer (or both failed).
- **mismatch** — they differed and the difference is *not* declared. This is a
  bug in the port; the harness reports it with `t.Errorf`.
- **deviations** — they differed and the case carries a `"deviation"` tag
  explaining why, which is also listed in the express submodule's
  `API-DEVIATIONS.md`. `../../../HARNESS.md` requires these to be counted
  separately from a bug, so they are excluded from `compared` and reported with
  `t.Logf`. `declaredDeviations` counts the tags; if it ever exceeds
  `deviations`, `staleDeviations` names the tags that describe a difference which
  no longer happens and should be deleted.

`parityPercent` is `match / compared`, i.e. over the cases where the two
implementations are expected to agree.

### Message-text differences

Upstream raises `TypeError("Invalid number")` for NaN and both infinities and
`TypeError("Invalid rounding method")` for an unknown `roundingMethod`. The port
has no error return at all — the finiteness guard lives in the harness runner,
which is why those four cases compare as "both failed" rather than comparing
text.

## Declared deviations

None. The suite is at 100%.

## Untested

| surface | why |
| --- | --- |
| the fifteen unported options above | `missing`; a case would compare a feature only one side has |
| `partial(options)` | `missing`; it is sugar over the same code path, which `filesizeOpts` cases already cover |
| `TypeError("Invalid rounding method")` | reachable only through `options.roundingMethod`, which is not ported |
| `bigint` input | upstream accepts `BigInt`; Go's `float64` signature cannot represent one, and JSON has no bigint literal, so there is no shared input |

## What the harness fixed

3 of 188 cases failed at first run, all at the top of the range: upstream renders
a mantissa of 1e21 or more the way JavaScript stringifies a `Number`
(`"1e+36 YB"`), while the port always used fixed notation
(`"1000000000000000042420637374017961984 YB"`). `formatNumber` now switches to
exponential notation at the same threshold.
