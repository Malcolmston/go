# `express/prettybytes` vs `pretty-bytes` — API coverage

- **Upstream (oracle):** `pretty-bytes@7.1.1` (sindresorhus/pretty-bytes), pinned
  in `node/package.json`.
- **Port:** `github.com/malcolmston/express/prettybytes`.
- **Score:** see `parity.json`, regenerated by `GOWORK=off go test .`.

## How the upstream inventory was derived

```sh
cd node && npm install
node --input-type=module -e '
  const ns = await import("pretty-bytes");
  console.log(Object.keys(ns), typeof ns.default, ns.default.length);
'
# [ "default" ] function 2
```

One export, no properties. The option keys are spread inside the function rather
than destructured in the signature, so they were read off the installed
implementation:

```sh
grep -n "options\.\|\.\.\.options" node/node_modules/pretty-bytes/index.js
# defaults: bits, binary, space, nonBreakingSpace
# read:     options.bits, options.binary, options.space, options.nonBreakingSpace,
#           options.signed, options.locale, options.fixedWidth,
#           options.minimumFractionDigits, options.maximumFractionDigits
```

## How the score is counted

`parity.json` separates three outcomes, and `go test` fails only on the middle
one:

- **match** — both implementations gave the same answer (or both failed).
- **mismatch** — they differed and the difference is *not* declared. This is a
  bug in the port; the harness reports it with `t.Errorf`.
- **deviations** — they differed and the case carries a `"deviation"` tag
  explaining why, which is also listed in the express submodule's
  `API-DEVIATIONS.md`. `../../../HARNESS.md` requires these to be counted
  separately from a bug, so they are excluded from `compared` and reported with
  `t.Logf`. `declaredDeviations` counts the tags; if it ever exceeds
  `deviations`, `staleDeviations` names the tags that describe a difference which
  no longer happens and should be deleted.

`parityPercent` is `match / compared`, i.e. over the cases where the two
implementations are expected to agree.

### Message-text differences

Upstream raises ``TypeError(`Expected a finite number, got ${typeof number}: ${number}`)``.
The port returns a string instead (see the deviation), so no case compares text.

## Declared deviations

Listed in the express submodule's `API-DEVIATIONS.md`.

1. `err-nan`, `err-infinity`, `err-neg-infinity` — `PrettyBytes` and
   `PrettyBytesOpts` return `string`, with no `error`, so they cannot raise the
   way `prettyBytes` does on NaN or ±Infinity. The port formats the value through
   Go's float formatter (`"NaN B"`-style output) instead of failing. Changing this
   would mean either panicking, which is not idiomatic for a formatting helper, or
   widening the signature of a shipped API.

## Untested

| surface | why |
| --- | --- |
| `options.locale` | not ported (`missing`). The port's grouping is fixed at `en-US`, so the oracle is pinned to `en-US` rather than left to the machine's default ICU locale — that keeps the fraction-digit cases deterministic, but it means no case measures a *different* locale |
| `options.space`, `options.nonBreakingSpace`, `options.fixedWidth` | not ported (`missing`) |
| `bigint` input | no shared input representation |

## What the harness fixed

4 of 190 cases failed at first run because the port always used fixed notation
while upstream concatenates a JavaScript `Number`, which switches to exponential
form outside `[1e-6, 1e21)`: `1e-9 B` not `0.000000001 B`, `1e+76 YB` not a
77-digit integer. `jsNumberString` now reproduces `String(Number)`, including the
unpadded exponent (`1e-9`, not `1e-09`), and `formatPrecision` now follows
upstream's `minPrecision = max(3, String(Math.floor(n)).length)` rule.
