# Cross-language parity harness

Every `malcolmston/*` library is a port of something that already exists. This
harness answers the only question that matters for a port — **does it do what the
original does** — by running *both* implementations over the same inputs and
comparing their answers. Expectations are never hand-written: upstream is the
oracle, so a new upstream release re-scores the port for free.

## Layout

One directory per Go sub-repo. Inside it, the upstream implementation and the Go
implementation live in **separate sibling folders**, each holding a *runner*, and
the cases they are both fed live in `cases/`:

```
parity/<lib>/
├── cases/                     # the questions, as JSON — language-agnostic
│   ├── <group>.json
│   └── <group>.json
├── <lang>/                    # upstream runner: node/ python/ java/ ruby/ rust/ elixir/ c/
│   └── run.<ext>              #   + package.json / pom.xml / Cargo.toml / mix.exs as needed
├── go/
│   └── run.go                 # Go runner (package main)
├── parity_test.go             # the harness — go test drives both runners and compares
├── go.mod                     # module github.com/malcolmston/go-parity/<lib>
├── COVERAGE.md                # full upstream API inventory vs the port (see below)
└── parity.json                # machine-readable score, regenerated by the test
```

`<lang>` is named for the upstream ecosystem, not the package: `node`, `python`,
`java`, `ruby`, `rust`, `elixir`, `c`.

## The runner contract

Both runners are **plain subprocesses speaking JSON Lines on stdio**. That is the
whole reason this works across seven languages: the harness never links against
the upstream library, it only talks to it.

Each runner reads one JSON object per line from stdin and writes exactly one JSON
object per line to stdout, in the same order:

```jsonc
// in
{"id": "bold-basic", "fn": "bold", "args": ["hello"]}
// out — success
{"id": "bold-basic", "ok": true,  "value": "[1mhello[22m"}
// out — the call threw/panicked/returned an error
{"id": "bold-basic", "ok": false, "error": "invalid hex colour: nope"}
```

Rules that make comparison meaningful:

- **Never exit on a failing case.** Catch the throw/panic/error, report
  `ok:false`, and keep reading. A crashed runner scores every remaining case as a
  loss.
- Write nothing else to stdout — logs go to stderr.
- `value` must be JSON-comparable: prefer strings, numbers, bools, arrays and
  plain objects. Encode bytes as lowercase hex, and note the encoding in the case.
- Be deterministic: fixed seeds, fixed timestamps, fixed iteration order. Sort
  map keys before emitting. If upstream is inherently unordered, sort on both
  sides.
- Flush after every line (`process.stdout.write`, `sys.stdout.flush()`,
  `os.Stdout.Sync()`, …) or the harness will deadlock waiting for a reply.

## Case files

```jsonc
{
  "group": "colours",
  "upstream": "chalk@5.3.0",        // exact pinned upstream version
  "cases": [
    {
      "id": "hex-invalid",          // unique within the library
      "fn": "hex",                  // logical operation, same name for both runners
      "args": ["nope", "x"],
      "upstreamFn": "chalk.hex",    // real upstream symbol, for COVERAGE.md
      "goFn": "chalk.Hex",          // real Go symbol
      "note": "both sides must fail"
    }
  ]
}
```

- Pin the upstream version exactly. An unpinned oracle makes the score
  unreproducible.
- **Errors are cases too.** A port that returns a value where upstream throws is
  not at parity, so compare failures as well as successes. Match on *whether* it
  failed, not on message text — record message differences in `COVERAGE.md`
  instead.
- Where a difference is deliberate, keep the case and mark it
  `"deviation": "why"`. The harness counts it separately from a bug; it must also
  be listed in the library's `API-DEVIATIONS.md`.

## The harness (`parity_test.go`)

`go test ./parity/<lib>/` must:

1. Build/install both runners, skipping with `t.Skip` (never failing) when the
   upstream toolchain is absent — `exec.LookPath` first. A missing Node must not
   turn into a red build for someone who only has Go.
2. Start each runner **once** and stream every case through it; do not spawn a
   process per case.
3. Feed identical cases to both, compare `ok` first and then `value` with a
   normalising deep-equal (ints vs floats: `1` and `1.0` are equal; treat all JSON
   numbers as float64).
4. Report each mismatch with the case id, the upstream answer and the Go answer,
   via `t.Errorf` — one subtest per case using `t.Run(c.ID, …)`.
5. Enforce a per-case timeout so a hung runner fails that case, not the suite.
6. Rewrite `parity.json` with the totals.

## `COVERAGE.md` — the API inventory

This is the deliverable that makes the parity claim auditable, and it is the part
that must not be hand-waved. **Enumerate every exported symbol the upstream
library has**, then state what the Go port offers for it:

| upstream symbol | Go symbol | status | cases | note |
| --- | --- | --- | --- | --- |
| `chalk.bold` | `chalk.Bold` | match | `bold-basic`, `bold-nested` | |
| `chalk.hex` | `chalk.Hex` | differs | `hex-invalid` | Go returns error, JS throws |
| `chalk.ansi256` | — | missing | — | not ported |
| — | `chalk.VisibleLength` | extra | `width-cjk` | Go-only helper |

Derive the upstream list mechanically, not from memory or from the README —
`Object.keys` / `dir()` / `javap` / `cargo doc --json` / reflection over the real
installed package — and say in `COVERAGE.md` exactly which command produced it.
Every symbol gets one of: `match`, `differs`, `missing`, `extra`, `untested`.
Finish with counts and a parity percentage over the symbols actually compared,
plus the case total. A symbol with no case is `untested`, never `match`.
